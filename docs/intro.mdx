# Introduction

**Eigen** is an open-source, server-authoritative engine for **turn-based
multiplayer games**. One codebase runs many games; each deployment is a single
Cloudflare Worker that owns its own domain, database, and players.

The rules run on the server, so a client's move is always a proposal the server
validates — hidden information never leaves the server except as a per-seat
projection, clocks are authoritative, and finished games are replayable from an
immutable log.

You write pure game rules. The engine owns persistence, serialization, timing,
sockets, reconnection, ratings, bots, auth, history, the API, and the game's
website.

## How these docs are organised

The documentation is **audience-first**: the top-level sections match who you
are, and each one runs from tutorial through how-to to explanation.

- **Getting started** — run the reference game, then read it.
- **Build a game** — the `GameRules` contract, hook by hook, plus testing, CI
  and versioning.
- **The Flutter client** — the transport, the Dart rules twin, the app shell,
  and everything involved in shipping to a store.
- **Operate** — configuration, local development, deploying, the generated web
  surface, and the account lifecycle.
- **How it works** — the engine itself: the kernel, Durable Objects, storage,
  identity, security and the failure model.
- **Reference** — the HTTP API (generated from `openapi.json`), the TypeScript
  API (generated from source), the Envelope contract and the error model.
